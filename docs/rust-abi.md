# Release bridge ABI and lifetime audit

The assumptions below belong to the profiled macOS ARM64 release. The [Rust ABI reference](https://doc.rust-lang.org/reference/items/external-blocks.html#abi) gives the native Rust ABI no stability guarantees. The [layout reference](https://doc.rust-lang.org/reference/type-layout.html) guarantees only limited properties for default Rust layouts and gives closures no layout guarantee. The AArch64 procedure-call standard defines `x8` for indirect results. The decision to use that convention for each particular Rust call and its lowered argument list came from the target’s machine code. [AAPCS64](https://github.com/ARM-software/abi-aa/blob/main/aapcs64/aapcs64.rst)

| Assumption | Basis and runtime guard | Failure mode |
| --- | --- | --- |
| The matched divider call returns its `Div` indirectly through `x8`. | Disassembly shows the caller setting `x8` to `sp + 0xaf0` before `BL`. The agent checks both instruction words, captures `x8` at entry, and filters by the return address. | The bridge could overwrite unrelated stack storage. |
| Constructors and concrete `Div::child<T>` specializations have the profiled signatures. | Disassembly of call sites and callees established argument registers, Rust string pointer and length pairs, and output slots. `v_flex` gets the existing compiler-generated `Location` pointer. UUID and selected words are checked. The full signatures and location pointer are not independently validated. | Incorrect register interpretation, pointer dereference, or object construction. |
| Scratch has adequate sizes and alignment. | The profiled `Div` move is `0x548` bytes. `Label` writes through `+0x5d0` and `Button` through `+0x878`. Checks cover those instructions. The bridge uses two `0x550` slots, one `0x8a0` element slot, and text arguments starting at `0x1340` within `0x1360` bytes of heap scratch. It assumes allocation alignment and preserves the observed stack alignment with a `0x20` frame. | Out-of-bounds writes or misaligned storage. Earlier debug and release experiments crashed with inadequate scratch or excessive stack use. |
| Child builders consume their inputs. The final byte copy is a move. | Observed caller/builder behavior and the source builder’s by-value API support this interpretation. Scratch alternates input/output slots. Moved-from bytes are never dropped. A move-size instruction is checked. There is no runtime ownership or destructor verification. | A stale copy, leak, double drop, invalid access, or partially modified parent after failure. |
| The click listener is a boxed zero-sized Rust closure with the profiled layout. | Selected Finish button stores and the original vtable header are checked. The bridge writes sentinel `1` at `Button + 0x648` and a vtable pointer at `+0x650`. The fabricated vtable has null drop, size `0`, alignment `1`, and three slots pointing to one Frida callback taking four pointers. Only the observed mouse invocation is verified. The check does not establish every vtable slot’s semantics. | Invalid dispatch or drop, incompatible function ABI, or use-after-free. |
| Text, vtable, and callback remain live for their consumers. | `strdup` allocates process-lifetime text for static slices. The shipped strings are ASCII, so JS string length equals byte length. The agent keeps the callback and vtable referenced. GPUI can retain them in the active frame. There is no quiescence test. | Dangling vtable or callback after unload. Quit the process before detaching. |
| Calls execute inside the original GPUI foreground render or input phase. | The matched composition call and native mouse delivery supply these contexts. The agent performs no separate thread check or reentrancy guard. The callback ignores borrowed event, `Window`, and `App` pointers. | Reentrancy or stale borrows if a future operation calls back into GPUI from the wrong phase. |
| Frida can install executable instrumentation in the local test process. | The agent rejects a required Frida signing policy, emits the bridge through `Memory.patchCode`, checks the executable protection transition, and attaches an interceptor. The local copied bundle is signed and verified before launch. | Agent installation or attachment fails. A marker alone does not establish that Zed reached onboarding. |

Source references: [identity and fingerprints](../examples/zed-release-card/zed-release-card-arm64.js#L1-L58), [closure and allocation](../examples/zed-release-card/zed-release-card-arm64.js#L60-L115), [builder calls, move, and protection](../examples/zed-release-card/zed-release-card-arm64.js#L125-L184), and [hook scope](../examples/zed-release-card/zed-release-card-arm64.js#L186-L219).

There is no transactional rollback after the bridge starts mutating the parent. Moving the bridge to Rust, Frida RustModule, or Gum does not make calls into the target’s private Rust ABI stable. A versioned interface can keep these assumptions inside the compatibility adapter.
